**Status:** PREPARED ONLY — tracking off by default; not deployed or approved for collection.

**Scope:** public marketing website only, based on `fix/app-store-launch-20261121` (PR #20), not the obsolete `main` source. Existing `app/free-pack/PackFunnel.tsx` uses a separate optional consent-gated direct gtag implementation. The current plan in `docs/WEBSITE_MEASUREMENT_PLAN_20261106.md` remains the baseline.

## Prepared
- `GTM-MR9TX63R` stored as a **public container identifier**, not a GA4 measurement ID and not a secret.
- `WebsiteMeasurement` loads no third-party script when the flag is off.
- If `NEXT_PUBLIC_WEBSITE_GTM_ENABLED=true` in an isolated test environment, show explicit Allow / Decline controls. No GTM script or measurement events are sent before Allow; decision is tab-session only and not inherited as email consent.
- After Allow, publish **only** `ic_public_page_view`, `ic_app_store_open` and `ic_web_app_open` through a local `dataLayer`. Fixed category-only URL, empty referrer, event name and page group only; no form fields, member identity, articles, health, journal or finance data. App Store/web app click is *intent*, not download/install/signup/payment.
- Exclusions: `/app` and descendants, `/free-pack` and descendants, `/api` and `/review`. On a client transition from a measured page to an excluded one, reload before proceeding to prevent inherited GTM runtime.
- On Decline after consent, disable consent and reload; clear first-party GA cookies. A server-side provider or third-party cookie cannot be cleared by this website code.
- No tag changes, GA4 properties/streams, app SDKs, revenue events, purchases, provider settings, deployments or charges.

1. Owner creates/selects a single **GA4 Standard** property: Iron Compass AI; reporting zone Australia/Brisbane; currency AUD. Obtain a web stream `G-...` measurement ID. Do not confuse the `GTM-...` container ID with the GA4 stream.
2. Inspect the **published** GTM-MR9TX63R container and every existing tag, trigger, consent requirement and environment to check whether it already sends GA4 or automatic page views; remove duplicates. No GTM account or container permission was available to this read.
3. Configure exactly one **Google tag** in GTM against the owner-selected GA4 stream with **automatic page-view emission disabled**, advertising off, Google Signals off, enhanced measurement's form/search/outbound/file options off, minimum supported retention, and no user-provided data. Require actual analytics consent before every GA4 tag/event; do not use unconditional All Pages triggers. Configure mapping for `ic_public_page_view` to a single normalised `page_view` and `ic_app_store_open` / `ic_web_app_open` to corresponding event names, preserving the page group and scrubbed URLs. The GTM container itself is loaded only after opt-in.
4. The feature flag `NEXT_PUBLIC_WEBSITE_GTM_ENABLED` must remain absent/false until the exact GTM configuration, privacy policy updates, and a synthetic preview have passed. The existing `NEXT_PUBLIC_PACK_GA4_ID` remains separate and should not be wired to a duplicate tag.
5. Re-review data handling with the actual GTM configuration, consent-mode semantics, vendor cookies and applicable privacy obligations before enabling. Existing free-pack policy copy is not broad site-wide consent wording. Keep consent UI accessible, concise and reversible.
6. Test with **GTM Preview/Tag Assistant** and GA4 DebugView/Realtime on a dedicated test stream: zero Google network requests before consent; one and only one `page_view` per landing and route change; one click event for one link activation; no collection on excluded pages; none on Decline; no persistent consent on reload/new session (per approved policy); no raw path/query/referrer/account data; no conversion on failed signup or click. Confirm app front-end, API, native purchases and payment provider remain unmodified.
7. If approved, document the exact PR commit, GTM version, stream ID, test evidence, retention and rollback. Use existing website verification gates; do not create another daily job or duplicate test suite. Release remains a separate, owner-approved stage/test/promote decision.

**Out of scope:** Native app installations, registration, subscriptions, revenue, cross-device attribution and member identity. Reconcile app and payment provider events with account-consented instrumentation as a separate workstream, using confirmed provider events as truth.

**Stop condition:** Do not activate if GTM emits any automatic page view before consent, any extra GA4 tag fires, sensitive information enters a payload, the privacy wording is insufficient, or no owner-controlled GA4 stream can be verified.
